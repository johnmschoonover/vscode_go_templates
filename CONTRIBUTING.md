# Contributing to Go Template Studio

Thanks for your interest in improving Go Template Studio! This guide covers local setup, the checks every change should pass, and what we expect from pull requests.

## Prerequisites
- Node.js 18 or newer and npm
- Go 1.21 or newer (used by the renderer worker in `go-worker/` and for template tests)
- Visual Studio Code 1.85 or newer

## Setup
1. Fork and clone the repository.
2. Install dependencies with `npm ci` (or `npm install` when updating the lockfile).
3. Build the extension with `npm run compile`.

## Running from Source
1. Open the repository in VS Code.
2. Press `F5` and choose the **Run Extension** launch configuration. A new Extension Development Host window opens with the extension loaded.
   - For automatic rebuilds, run `npm run watch` and choose **Run Extension (Watch)** instead.
3. In the Extension Development Host, open `templates/asdf.go.tmpl` and run **Go Template Studio: Preview Template**.

Development builds fall back to `go run` when no bundled renderer binary exists under `assets/bin/`, so a local Go toolchain is all you need. In `auto` mode the status bar shows a warning icon for this fallback. Set `goTemplateStudio.rendererMode` to `system` to silence it. Use the `goTemplateStudio.rendererMode` and `goTemplateStudio.goBinary` settings to force a specific renderer.

The worker's Go dependencies are vendored in `go-worker/vendor/` so the `go run` fallback works offline. After changing `go-worker/go.mod`, run `go mod vendor` in `go-worker/` and commit the result. Check formatting with `gofmt -l main.go main_test.go` (the vendored files are left as upstream wrote them).

## Workflow Checks
Run these before opening a pull request; CI runs the same checks:

```sh
npm run lint
npm run typecheck
npm run compile
npm run test        # Go renderer tests (go-worker)
npm run verify:grammar
```

An optional `pre-commit` configuration (`.pre-commit-config.yaml`) runs these checks automatically before each commit if you install it locally.

## Vendored TextMate Grammar
The syntax highlighting grammar in `syntaxes/go-template.tmLanguage.json` is vendored from [`jinliming2/vscode-go-template`](https://github.com/jinliming2/vscode-go-template).
- Run `npm run update:grammar` to refresh the grammar and license snapshot.
- Run `npm run verify:grammar` to confirm the vendored files match upstream.
- Do not hand-edit the vendored files; contribute grammar fixes upstream instead.

## Marketplace Icon
The extension icon is generated by `scripts/generate-icon.py` (requires Pillow). Run `python3 scripts/generate-icon.py` to regenerate `assets/icon.png` and `assets/icon.svg`.

## Pull Request Expectations
- Keep changes small and focused; prefer incremental steps and leave clear TODOs over speculative end-to-end implementations.
- Align with the requirements in [`PRD.md`](PRD.md) and [`technical_spec.md`](technical_spec.md). Reference the relevant requirement for larger functional changes.
- Make sure lint, typecheck, compile, and tests pass.
- Update `README.md` and other docs when the user-visible surface changes, add an entry to `CHANGELOG.md`, and keep the status notes in [`ux_brief.md`](ux_brief.md) current.
- Route error reporting through `src/services/diagnosticService.ts` so VS Code diagnostics and the preview sidebar stay in sync.
- If requirements are unclear, open an issue or ask in the pull request instead of guessing, and document any assumptions in code comments or the PR description.
- Fill in the pull request template checklist.

The full repository guidelines live in [`AGENTS.md`](AGENTS.md); they apply to human and automated contributors alike.

## Reporting Bugs and Requesting Features
Use the [issue templates](https://github.com/johnmschoonover/vscode_go_templates/issues/new/choose) for bug reports, feature requests, and questions. For security-sensitive reports, please avoid public issues and contact the maintainer directly.
